# Reusable CAD modules

Hand-maintained registry of importable geometry helpers. For complete, buildable
models, use the generated [model catalog](README.md).

## Find and maintain modules

- Before constructing a model's features, check the index below and read the
  matching module entry. Import an existing helper when its interface and source
  scope match the required geometry.
- When adding a reusable helper, register it here in the same change. When
  changing, renaming, or removing one, update its entry and index links.
- Each entry must identify its purpose, source path and Python import, public
  parameters and units, returned geometry and builder side effects, local datum
  and orientation, placement/boolean example, and source/fit limitations. Link
  research evidence rather than copying the research record.
- Helpers live beside their model or in a shared project folder. Reserve
  `model.py` and `model.toml` for cataloged entrypoints; this registry is not
  generated by `scripts/index.py`.
- For geometry-changing helper edits, locate and rebuild all consuming models,
  recheck their interfaces, and reset their `print_tested` flags until the changed
  geometry is physically tested.

## Basic wooden-railway track

```python
from build123d import Pos
from models.brio_duplo.track.config import TrackConfig
from models.brio_duplo.track.geometry import build_track, check_track

config = TrackConfig(turn_radius=202, turn_angle=45, rise=18)
track = build_track(config)
check_track(track, config)
placed = Pos(100, 0, 0) * track
```

`build_track(config)` returns a fresh single-solid `Compound`/`Part` without
exporting or reading configuration files. It uses high-level constructors:
construct outside active builders, then explicitly insert the result; it is
not a builder-safe factory. `check_track(shape, config)` checks native or
reimported STEP material against the configured interfaces.
`TrackConfig` is frozen; lengths are mm and angles degrees. Public fields are
`length=54` (straight shoulder contribution), `turn_radius=202` (horizontal
centerline), `turn_angle=0` (signed left/right), `rise=0` (end minus start),
`double_sided=True`, `ends=("female", "male")` (start/end), and `end_flat=24`.
Turns use radius × absolute angle for horizontal path length; `length` is
ignored for curves. End connectors are independent male/female choices.

Start shoulder is at X=Y=0 with tangent +X and underside Z=0 for a rise.
A fall starts at Z=−`rise`, ending at Z=0. Plan curves turn left for positive
angles, right for negative. Connectors lie in horizontal end frames; grades
have level pads and a cubic eased elevation transition. Flat curves are exact
circular sweeps. Grades are smooth lofts through oriented sections at no more
than 3 mm horizontal spacing, with an independent ideal-route material check
using a 0.04 mm CAD sampling tolerance; this is not a manufacturing tolerance
or a global surface-error bound. No junction/splitter geometry is included.

Radius must exceed the 20 mm half-width; angle magnitude is below 180°.
Geometry rejects overlapping end-pocket spans, undersized level pads and
graded transitions whose ideal maximum slope exceeds 0.5 mm/mm. The
[model instructions](brio_duplo/README.md) describe TOML presets and printing.
Sources are [BRIO research](../research/objects/brio-wooden-track/README.md)
and [DUPLO research](../research/objects/lego-duplo/README.md); grooves, joints
and print allowances are approximate, with no verified factory fit or safety.

Consumers are `brio_duplo/track/model.py` and the default straight reference
in `brio_duplo/assembly/model.py`. Rebuild both and the exported variant matrix
when this module changes. The 12 exercised configurations passed native/STEP
interface and connector-mating checks and watertight STL/3MF validation;
artifacts and configuration-specific reports are under
`outputs/brio_duplo/variants/`. Physical print, clutch, retention, and wagon
running on curves/grades remain untested.

## ACME thread envelope

```python
from models.pole_l_bracket.thread import thread_envelope

# Construct outside an active builder; subtract this tool from a socket body.
socket_tool = thread_envelope(
    bottom=0, length=10.16, radial_allowance=0.2, axial_allowance=0.1,
)
```

`thread_envelope(bottom, length, radial_allowance=0.0, axial_allowance=0.0,
root_relief=0.0)` returns a fresh `Compound` containing one solid. All dimensions
are millimeters. The axis is world +Z, centered on XY; the tool is trimmed from
Z=`bottom` to Z=`bottom + length`. At +X, tooth centers are at
`bottom + n * PITCH`. Place the result with `Pos`/`Plane` before a boolean.

The fixed basic profile is 19.05 mm major diameter, 5.08 mm pitch and 29° included
flank angle. Zero allowances produce the basic male envelope; radial and axial
allowances enlarge the female cutting tool, and `root_relief` extends its crest
radius. Length must be positive and allowances nonnegative; a collapsed crest
or overlapping turns raises `ValueError`.

Unlike the Multiboard factories, this helper uses high-level build123d objects;
construct it outside active builder contexts, then explicitly insert the result.
It imports without building or exporting geometry. This is a basic ACME envelope,
not a certified thread tolerance class or a universal pole connector. See the
[existing socket consumer](pole_l_bracket/model.py) and its
[hardware research](../research/objects/cooptrypoul-b0d8bb46y6/README.md).

## Multiboard peg and rail cutout

These helpers return fresh build123d `Solid` objects; importing them does not
build geometry or export files. They also leave an active `BuildPart` unchanged.
Callers position the result and explicitly add/subtract it (or `insert` it in a
builder). Helpers are not catalog entrypoints and do not need `model.toml`.

```python
from build123d import Align, Box, Pos
from models.multiboard.peg import peg
from models.multiboard.rail import rail_cutout

# Add a snap-insert peg to a 3 mm plate; exposed projection stays 6.5 mm.
plate = Box(22, 22, 3, align=(Align.CENTER, Align.CENTER, Align.MIN))
peg_mount = plate + Pos(0, 0, 3) * peg(root_overlap=0.2)

# Cut a two-position rail receiver into a 5 mm plate, open at its Y=0 edge.
back = Box(23, 63, 5, align=(Align.CENTER, Align.MIN, Align.MIN))
rail_mount = back - Pos(0, 0, 5) * rail_cutout(repeats=2)
```

| Module / function | Parameters and local frame |
| --- | --- |
| [`peg.py`](multiboard/peg.py): `peg(*, across_flats=13.5, projection=6.5, root_overlap=0.0)` | Millimeters. Regular octagon centered on XY, axis-aligned flats at ±6.75 by default. Root plane Z=0; tip Z=`projection`; optional overlap extends below the root without changing exposed length. For insertion into a **snap**, not directly into the tile's large Multihole. |
| [`rail.py`](multiboard/rail.py): `rail_cutout(*, repeats=1, overrun=0.5)` | Millimeters by the documented source-unit assumption. Mouth plane Z=0; host is toward −Z; recess bottom Z=−2.2. X is width, Y runs from the entry toward the closed end. Repeated profiles overlap on 25 mm centers along +Y. `overrun` extends the first entry toward −Y and the mouth toward +Z; it is a cutting margin, not fit compensation. |

The nominal single rail tool spans X=±8.5, Y=0…33.5, Z=−2.2…0.
The default 0.5 mm cutting margin changes only its minimum Y and maximum Z.
Leave backing material below the recess and an unobstructed Y=0 entry; no latch
or retention mechanism is added. Rotate/place either tool with build123d
`Plane`/`Location`/`Pos` operations rather than changing its internal datum.
Positive dimensions must be finite; overlap/overrun must be finite and
nonnegative; repeat count must be a positive integer.

**Source scope:** the peg uses the author's selected
[13.5 mm × 6.5 mm AirTag precedent](../research/objects/multiboard/measured-connectors.md).
That listing declares Attribution–Noncommercial–ShareAlike, with its exact
version still unresolved in the research record; retain its attribution and
applicable terms when sharing source-derived geometry. The rail module adapts
haliphax's MIT-licensed
[`fix-point-slot.scad` at `95a37a6b`](https://github.com/haliphax/multiboard-openscad/blob/95a37a6b75fe3feaac61db63dfac0576480ac1df/parts/fix-point-slot.scad),
with the copyright/permission notice retained in the module. It preserves the
two published 14-point profiles, but uses a ruled CAD loft instead of the
source's epsilon-cube hull construction and replaces its host-specific placement
with the frame above. This is a **community Fix-Point cutter**, not a verified
official Lite/Regular profile or a confirmed mate for the supplied folded rail.
See the [source comparison](../research/objects/multiboard/community-parametric-sources.md).

Both standalone tools and the two boolean examples passed native/STEP checks
and watertight single-body STL export. Generated inspection previews live under
`outputs/multiboard/{peg,rail_cutout,peg_coupon,rail_receiver_coupon}/`; they are
ignored artifacts, not cataloged models or print-test evidence.

## Multiboard holder finishing

The shared [finish module](multiboard/finish.py) defines
`OUTSIDE_CORNER_RADIUS = 3.0` and `EDGE_RADIUS = 0.6`, in millimeters.
All new Multiboard holder bodies use **R3 convex outside plan/free-end profile
corners and R0.6 exposed top/bottom/cutout edges**. These are distinct feature classes,
applied consistently, not per-model guesses. Functional device-seat contours
may use measured radii; square support datums and concave floor/wall joints
stay intact. Snap pegs are added afterward with mating geometry unchanged.
Already-completed XIAO, C6L and Cardputer geometry is intentionally excluded.
Pocket V1's free upper ends use the same R3 profile radius before the R0.6 edge
round. Keeping profile and edge radii distinct avoids coincident spherical-pole
triangulation failures while retaining the requested rounded side access.

```python
from build123d import Align, Box, Pos
from models.multiboard.finish import rounded_blank

blank = rounded_blank(60, 16, 23)
cavity = Pos(0, 0, 2.5) * Box(
    55, 11, 24, align=(Align.CENTER, Align.CENTER, Align.MIN),
)
body = blank - cavity
```

`rounded_blank(width, depth, height)` returns fresh one-solid geometry centered
on XY, bottom Z=0, height along +Z: R3 vertical corners and R0.6 top/bottom
outside perimeter rounds. Width/depth must exceed 6 mm, height 1.2 mm.
`round_edges(edges)` returns the containing shape with R0.6 on an explicit
nonempty current-shape edge selection; callers check selection cardinality and
keep mating/support features out. Both use algebra constructors: call outside
active builders, then explicitly insert returned geometry. No import-time
geometry, export or viewer side effects. They fail rather than silently omit
requested rounds.

Consumers: X1, T1000-E, WisMesh Tag, T-Deck Plus, WisMesh Pocket V1, Station G2,
and circuit-board shelf. Rebuild all seven native/STEP models and inspect
exported previews after changes to this standard. This is a design convention,
not a strength or printability certification. Task: [#43](https://github.com/ShakataGaNai/b123d/issues/43).

## Multiboard slot-floor labels

```python
from models.multiboard.label import label_tool, check_label

dimensions = dict(floor_width=50, floor_depth=7, floor_height=2.5)
marked = body - label_tool("T1000E", **dimensions)
check_label(marked, "T1000E", **dimensions)
```

`label_tool(text, *, floor_width, floor_depth, floor_height, font_size=4.0)`
returns fresh cutting geometry spanning Z=`floor_height - 0.2`…`floor_height` mm.
Subtract from the flat inside floor. The font is the locked matplotlib package's `DejaVuSans.ttf`,
selected by explicit path and checked alongside its bundled license; missing
font/glyphs fail rather than silently substituting. Actual glyph bounds are
centered at X=Y=0 and must leave 0.25 mm margin within the given floor rectangle.
The floor must be thicker than 0.2 mm. All lengths and font size are mm.
`LABEL_DEPTH=0.2` is fixed; `LABEL_FONT_SIZE=4.0` is the default.

Text local +X/+Y maps to world +X/+Y, normal +Z, letter tops toward the board
(+Y), readable from the front (−Y) looking into the slot. This is a 180° flip
about Y from the former underside label. Construct outside active builders,
then explicitly subtract/insert; imports do not build or export.
`check_label(shape, text, *, floor_width, floor_depth, floor_height,
font_size=4.0)` raises unless the complete glyph cut, surrounding floor and
intact backing match. Its bounds tolerance accounts for OCCT curved-glyph
bounding-box expansion, not extra physical cut depth.

Consumers: X1 (`X1`), T1000-E (`T1000E`) and WisMesh Tag (`Wis Tag`).
Rebuild all three after geometry/font/orientation changes. A one-layer deboss
requires slicer and physical legibility checks; geometric verification is not
print evidence. See [text/font precedent](wifi_qr/README.md) and
[#43](https://github.com/ShakataGaNai/b123d/issues/43).
